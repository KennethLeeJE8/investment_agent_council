# Roadmap

The starting product is a repository-operated CLI with readable documents. A UI, permanent worker service, and paid agent platform are outside the initial scope.

## 1. Portable local foundation — implemented

Locked installation, blank configuration, explicit source ownership, HTML intake, hashes, bounded retrieval, isolated packets, Markdown output, local telemetry, and tests that generate temporary workspaces.

## 2. First live research pilot — pending

Add a provider adapter with explicit model selection, cancellation, retry limits, and per-run usage limits. Start with two relevant experts and a narrow question before increasing concurrency.

Acceptance: independent submissions cite inspected evidence; uncertainty and failed calls remain visible. No paid fallback is silently selected. Simulated results cannot enter real research memory.

## 3. Evidence and constructive discussion — pending

Add a claim register, evidence review, targeted challenges, bounded follow-up, revision history, and a final Markdown dossier. Support roles route and check claims rather than vote on truth.

Acceptance: disagreements become competing mechanisms or predictions; revisions identify the evidence that changed them. Reports distinguish technology success, value capture, and investor returns.

## 4. Context layers and durable execution — pending

Validate adapters for TiDB Starter state/checkpoints, Filesystem/Drive9 sources/artifacts, and mem9 private spaces plus controlled shared publication. Confirm protocol, region, credentials, and data scope before connecting.

Acceptance: interruption/resume preserves state; hashes and locators survive retrieval; expert state remains isolated; unavailable services and partial writes are explicit.

## 5. Six-expert evaluation — pending

Evaluate specialist distinctiveness, source quality, alternatives, abstention, and the contribution of each added expert. Build scientific and investment corpora from approved sources and counterpositions.

Acceptance: include English/Chinese material, failures and successes, and historical cases restricted to available information at the stated time. A polished explanation is not proof of predictive investment skill.

## 6. Optional operations — deferred

Add OTLP export, better retrieval, memory policies, remote foreground execution, or recurring research when usage justifies it. Hosting, UI, monitoring, and additional investment mandates need separate scope decisions.

Visibility, code license, maintainer/security contact, and publication timing remain owner decisions. See [GitHub preparation](GITHUB_PREPARATION.md).
